# ぷにちゃんアップデート 設計書（v2）

- 日付：2026-10-01
- 対象：`js/`・`css/style.css`・`index.html`・`sw.js`（`VERSION` を `v2.0.0` へ）
- 前提：`CLAUDE.md` の「設計上の約束」をすべて守る（静的サイト・外部通信なし・CSP `'self'` のみ・ひらがな UI・キャラは死なない・旧データを消さない）

## 0. 目的と成功条件
- 目的：子どもが飽きずに毎日開きたくなるよう、反応・姿・セリフを増やし、一生（たまご→さいごのすがた→たまごを託す）に区切りをつける。生活リズムの習慣（おかたづけ・はやね・はやおき）を追加する。
- 成功条件
  - v1 の保存データ・`PUNI1:` 復元コードが、育成状態を保ったまま v2 で読める。
  - 時刻を進める確認（Playwright の `page.clock`）で、ねんね・タスクの受付時間・おとな→さいごのすがた→おわかれ→つぎのたまご が仕様通りに動く。
  - CSP 違反を含むコンソールエラーがない。iPad 幅（820×1180）で崩れない。

- 時間経過による おなか・ごきげん の減少と、びょうきの進行が止まる（v1 の 21:00〜6:59 から変更）。

- タスクの報告はできる（エサはトレイにたまる）。

## 4. 一生の流れ
### 4.1 段階
| stage | 段階 | 進み方 |
|---|---|---|
| 0 | たまご | 初期 |
| 1 | あかちゃん | 累計 3pt |
| 2 | こども | 累計 10pt |
| 3 | おとな | 累計 25pt。到達時刻を `adultAt` に記録 |
| 4 | さいごの すがた | `adultAt` の日付 + 2 日 の 6:00 以降（おとな期間 2〜3 日）。時刻を `finalAt` に記録 |
| — | おわかれ | `finalSeenAt` の日付 + 1 日 の 6:00 以降、ねんね帯でなく、びょうきでない時に、キャラをタッチ |

- `finalSeenAt`：さいごのすがた への進化モーダルを閉じた時刻（＝子どもが初めて見た時）。アプリを数日開かなくても、さいごのすがた を必ず 1 日見られる。
- おとな→さいごのすがた の判定は時間経過チェック（起動時・30 秒ごと・前面復帰時）で行い、進化モーダルを出す。ねんね帯の間は判定しない（朝に見られるように）。
- おわかれの準備ができると、バッジ「💌 ◯◯ が なにか いいたそう」を表示する。
- びょうき中は おわかれ しない（「げんきに なったら おはなし したいな」）。

### 4.2 おわかれイベント
1. キャラをタッチ → おわかれモーダル（背景タップで閉じない）。
2. 3 ページのあいさつ。「つぎへ」で進む。よびかた（設定されていれば）を使う。例：「◯◯、いままで ありがとう」「いっしょに いっぱい がんばったね」「そろそろ たび に でる じかん みたい」。
3. 「これ、◯◯ に わたすね」→ たまごを渡す演出 →「たまご を もらった！」。
4. 次の世代へ：`history` に記録を追加し、新しいたまごから開始。

- 引き継ぐもの：なまえ、よびかた、世代数 +1、ずかん・色違い・`history`、れっすん曜日、所持エサ、当日の日付と回数、ぐんぐんたいむ、音の設定。
- 初期化するもの：段階・姿・色違いフラグ・pt・つよさ・おなか・ごきげん・びょうき・時間の積算・`adultAt`/`finalAt`/`finalSeenAt`・`petAt`。
- v1 の 🥚 つぎのたまご ボタンは廃止する。

### 4.3 姿と分岐（ずかん 19 種）
分岐は進化する瞬間のつよさ `v = {ka, ki, ge, ho}` で決める。同値は かしこさ→きれい→げんき→ほかほか の順で先を優先。

- あかちゃん（たまご→）：最大のつよさ。ka→`puni` ぷにぷに（既存）、ki→`shizuku` しずくぷに、ge→`koro` ころぷに、ho→`moko` もこぷに。
- こども（あかちゃん→）：最大のつよさ。ka→`hoshi` ほしぷに（既存）、ki→`shabon` しゃぼんぷに、ge→`hana` はなぷに（既存）、ho→`kumo` くもぷに。
- おとな（こども→）：11 種
  - 1つ型：ka→`hakase`、ki→`kirara`、ge→`morimori`、ho→`pokapoka`（既存）
  - 2つ型：ka+ki→`tsukimi` つきみぷに、ka+ge→`bouken` ぼうけんぷに、ka+ho→`yumemi` ゆめみぷに、ki+ge→`marin` まりんぷに、ki+ho→`keki` けーきぷに、ge+ho→`ohisama` おひさまぷに
  - `niji` にじぷに（既存）

おとなの決め方：
1. 第1候補：4 つすべて > 0 かつ 最大/最小 ≦ 1.6 → `niji`。そうでなく 2 位 ≧ 1 位 × 0.75（かつ 2 位 > 0）→ 上位 2 つの 2つ型。それ以外 → 1 位の 1つ型。
2. 残りの候補を相性スコアの高い順に並べる。1つ型 X：`v[X]`、2つ型 XY：`(v[X]+v[Y])/2`、`niji`：`最小値 × 1.6`。同点は ずかん順。
3. 第1候補から順に見て、ずかん にまだ無い最初のおとなに決める。
4. 11 種すべて ずかん にある場合は、第1候補の **きらきら色違い**（`shiny: true`）。色違いを見た種類を `shinySeen` に記録する。

- あかちゃん・こども は重複してよい。
- 既存データの `hoshi`/`hana`/おとな5種はそのまま有効。

### 4.4 見た目
- すべてオリジナルデザイン（既存キャラの模倣禁止）。v1 の体の形を基本に、アクセサリ・色・耳の形で描き分ける。
- さいごのすがた：おとなの絵に、光の輪・小さな羽・まわりのきらきらを重ね、全体を少し明るくする。名前は「かがやく ◯◯」。
- 色違い：体色をパステル虹のグラデーションにし、✨を足す。名前は「きらきら ◯◯」。

### 4.5 ずかん
- 見出し「ずかん（発見数 / 19）」。段階ごとに あかちゃん・こども・おとな の小見出しを付ける。
- 未発見は v1 と同じ灰色シルエット＋ヒント。
- おとなの欄：`history` にその姿で旅立った子がいれば 👼 と「なまえ・◯ぴきめ」（最新 1 件、ほかに何人いるかは「ほか ◯ひき」）。`shinySeen` に含まれれば ✨。
- `history` はなまえを含む。表示は `esc()` を通す。

## 6. タッチ
`#pet` のポインターイベントで判定する。

| 操作 | 判定 | 反応 |
|---|---|---|
| あたま タップ | 上 40% をタップ | 「えへへ」系、照れ顔、💗 |
| おなか タップ | それ以外をタップ | 「くすぐったい」系、笑い声、💗 |
| なでなで | 押したまま合計 80px 以上動かす（1 回の押下で 1 回） | **鳴き声**、目を細める、💗✨、ごきげん+1 |
| ぎゅー | 700ms 以上ほぼ動かさず押す | 「ぎゅー！」、ハグ音、💞 |

## 8. セリフと中国語
- セリフは `data.js` に、場面（あいさつ・ひとりごと・タップ・なでなで・ぎゅー・食事・ねんね・びょうき・おわかれ）× 時間帯 × 状態ごとに用意する。各場面の合計は 10 以上。
- `{you}` を含むセリフは、よびかた が設定されている時だけ使う（置き換えた文字列は `textContent` で出す）。
- ひとりごと：起きていて、モーダルが無く、90 秒操作がない時に、状況に合ったセリフを 1 つ出す（音なし）。
- 起動時・前面復帰時のあいさつは時間帯で変える（あさ「おはよう」等）。
- 中国語：単語 30 語以上＋短い文 25 以上。形式は `[簡体字, ひらがな読み, いみ]`。吹き出しは「「よみ」は ちゅうごくご で「いみ」だよ！」＋簡体字。話すのは中国語系のエサを食べた時・こども以上をタップした時の 30%。

### 移行（v1 → v2）
- `lessonDay` → `lessonDays: [lessonDay]`。
- stage 3 → `adultAt` = 読み込み時刻（そこから 2〜3 日でさいごのすがた）。
- `lastCare` は捨てる。v1 で病気中ならそのまま病気（`cure` 維持）。
- `you`=''、`sound`=true、`zeroAcc`=0、その他の新キーは初期値。
- `sanitize()` は v1/v2 どちらの入力も受け、常に v2 を返す。

### バックアップコード
- 出力：`PUNI2:` ＋ Base64（UTF-8 JSON）。入力：`PUNI1:`／`PUNI2:` のどちらも受け、`sanitize()` を通す。長さ上限は 40,000 文字（`history` 分を見込む）。

## 11. エラー処理
- 保存・音・読み上げ・Service Worker・クリップボードの失敗はすべて握りつぶし、ゲームを止めない（v1 と同じ方針）。
- 読み込み失敗時は初期データで開始（v1 と同じ）。ただし移行で例外が出た場合も同様。

## 12. 確認方法（Playwright MCP）
